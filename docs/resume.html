01

Agent Memory 设计

把「动态注入」做成槽位竞价式预算分配:六个槽位在 窗口 − 输出预留 − 安全余量 内按硬下限 + 弹性系数 + 目标份额竞价,每步重建 prompt 而非追加,余量优先流向最不弹性的槽位 —— 这两条规则共同保证检索记忆永不挤出角色人格与操作契约,该失效模式有专门回归测试。

记忆冲突由显式 ConflictPolicy 解决,默认置信度优先而非后写胜 —— 后写胜会让一次幻觉抽取摧毁已验证的事实,这个默认值是被一次 0.3 置信度覆盖 0.95 置信度事实的真实故障改出来的。记忆层有独立的 precision@k / recall@k。

压缩仅在 step 边界且占用 >70% 时触发(中途压缩会打断推理链),且在压缩不会实际缩短时中止。每次构造产出可审计的 LedgerRecord(各槽位配额 / 占用 / 淘汰项及原因)。

实测6k 窗口下移除压缩机制使每步 token +15.7% 且额外驱逐 597 tokens;该效应在 12k 窗口以上消失 —— 机制的临界点由窗口扫描测出,而非假设。
02

Agent MCP 设计

工具表示由「注入 JSON schema」改为 tools/list → Python 模块编译链路(必需参数排序、标识符净化),Agent 在沙箱内 import 并通过 help() 按需发现细节。

工具选择由双阈值检索门控决定:IDF 加权覆盖率 + 绝对信息量,并配停用词表 —— 小语料下 IDF 无法自行折扣停用词。

实测每步实付工具签名 188 tokens,且与注册表规模无关;同规模全量 JSON schema 在 320 个工具时达 48,195 tokens —— 已超出整个 32k 窗口。这是工具编译方案相对 schema 注入的硬理由。
03

Skill 设计

技能命中改用与工具同一套 IDF 覆盖率门控:原先的 BM25 分数阈值在小语料下会把「礼貌问候用户」判为相关技能 —— 分数尺度本身不可比,阈值因此没有含义。

上下文吃紧时技能槽先丢正文保索引而非整体丢弃,Agent 仍然知道自己有哪些技能、可以再取。

04

A2A 协作设计

权限模型收敛为一个不接受租户参数的函数 may_delegate(source_id, target_id, *, need_files):缺失即拒绝(无默认放行、无通配)、租户是关系行上的列而非请求里的字段(调用方无法靠声明租户来授权跨租户委托)、授权有方向、文件传输是独立权限、自委托最先被拒,拒绝原因指明具体条件。

子 Agent 派生的目的不是并行,而是父级不必持有子级工作上下文:子级获得全新 ledger、空历史与独立工作区子树;父级只回收摘要与产物路径、永不回收子级 transcript;文件经共享工作区交接。成本按 Agent 维度独立归属,可回答「哪个子 Agent 烧掉了额度」。

05

Code Execution 执行基底(替代 Function Calling)

把 Agent 的唯一动作改为「在沙箱内写 Python」:工具是可 import 的模块而非 JSON schema,中间产物落盘、仅 stdout 回流上下文。该单一决策同时解决三件事 —— 上下文增长受「Agent 主动选择输出的内容」约束而非数据体量;第 40 步可读第 3 步的产物;崩溃恢复是重读工作区而非重放对话(工作区即 checkpoint)。

小模型写错代码是常态,故收敛循环按错误类别而非消息文本识别重复(name 'df' is not defined 与 name 'tbl' … 是同一误解的重复,不是两个错误)。反馈含异常类型、从 Agent 自身代码引回的失败行,以及被误用模块的真实签名重新注入;升级有界:同类两次 → 更强模型,三次 → 人工,之后中止。

实测单份 10-K 全文 61,206 tokens,已超出 32k 窗口 —— 这是该设计的前提,而非事后解释。
06

生产化沙箱、服务层与运行观测台(全栈)

沙箱双后端(Docker --network none / 进程受限兜底),结果强制记录自身隔离级别;容器 10 项隔离属性由测试对活跃 daemon 逐条验证:非 root、内核级断网、只读根文件系统、内存 OOM、墙钟、禁止装包、traceback 行号对齐等。无网络沙箱经文件 RPC 桥调用宿主工具,使宿主 broker 成为唯一可审计的出网收口。

服务层 FastAPI 28 个端点 + 每 run 一条 WebSocket;读开放、写操作过 token、渠道 webhook 走平台签名。SQLAlchemy 持久化 Agent 声明、A2A 关系、会话与运行记录 —— 运行记录只是索引,不复制产物。Redis 会话层带诚实的内存兜底并明示降级原因与多 worker 风险。

渠道接入(飞书)的验签与幂等由路由统一强制,适配器无法遗漏 —— 任何渠道都会在 200 慢响应时重投,而 Agent 运行天然慢,没有去重就会同一条消息起两个 run。同步 Agent 循环与异步 API 用有界线程池 + 每 run 事件队列桥接,取消是协作式的并明确告知在下一个步边界生效。

前端是运行观测台而非管理后台:核心是每步 token 槽位分配的实时可视化 —— 把「槽位竞价 + 硬下限」从一句话变成可以指着看的图。无构建步骤、无框架。

07

评测体系与自主性量化对照(项目信誉所在)

基于 SEC XBRL 半自动构造真值集 —— 这是 177 案例规模可行、人工标注只能到几十条的原因。映射层解决四类真实数据陷阱:一字段多标签、fy 标注的是填报年度而非事实年度、季度区间事实与年度同形、重述导致同期双值。

四类自动指标各自捕捉其余三者看不见的失效:数值准确率(三档容差,区分舍入与胡说)、引用可验证率(数字对但引文不在原文 = 猜的)、计算一致性、拒答正确性。judge 报告自身 Cohen's κ 校准,低于 0.6 的维度从 headline 撤出 —— 一个与人类不一致的 judge 不构成对 Agent 的证据。

Harness 只在「无测试替身」且「确有真实模型 token 消耗」时才认定为测量,否则显式标注 NOT A MEASUREMENT。这条守卫的每一半都源于真实发生过的失败:scripted provider 拿到 1.000 满分仍被拒绝;无凭据运行输出一屏零却曾被标记为有效。

另实现固化 DAG 对照组,与 Agent 组共享同一套语料、工具、指标与 harness,仅「由谁决定下一步」不同 —— 这使自主性对比成为测量而非争论。

接入新场景只允许新增 AgentSpec + 工具模块,不允许修改 runtime 任何一行 —— 由 AST 检查与三场景端到端测试强制。实测新场景平均 288 行、runtime 改动 0 行。

实测真值集 177 案例、0 隔离 0 错误、资产负债表恒等式 177/177 通过且相对误差 0.0;零模型地板线数值 0.571 / 引用 0.985 / 拒答 0.964;固化管道存在 0.738 的硬天花板、26.2 个百分点结构不可达 —— 固化管道能修补遗漏,修不了错误。

个人贡献:负责 Agent 后端核心能力开发,重点实现 Memory 上下文注入(槽位竞价预算与冲突策略)、MCP 工具扩展 (模块编译与检索门控)、Skill 能力管理、A2A 协作链路与权限模型,并主导执行基底由 Function Calling 迁移至 Code Execution、沙箱隔离与服务层落地,以及真值集与评测体系建设 —— 提升 Agent 的持续工作、工具扩展和多智能体协同能力,并使平台的每项能力主张都有可复现的实测支撑。

H

这个项目最该被记住的三句话

01
「一个固化管道能修补它的遗漏,修不了它的错误。」

由天花板分解量化:26.2 个百分点在结构上不可达,因为模型节点只在未答出时触发。不需要模型即可确立。

02
「约束模型能碰什么,不等于约束它能错到什么程度。」

我在文档里写下「模型只提供科目名,所以注入不了数字」,一个 stub 模型一次运行就证伪:同一个 caption 让七个字段拿到同一个真实数字、全部归属错误。声称被测试推翻,于是加了双重门控。

03
「记录错误的长度不是可观测性。」

trace 原本只记 stderr_chars,导致第一次真实运行的五次沙箱失败完全无法诊断 —— 在一个以可观测性为卖点的项目里。修复后同一案例从 0/12 变成 9/12。
